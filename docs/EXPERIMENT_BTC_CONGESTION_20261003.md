## 입력 자료와 가용 시계

1. Blockchain 공식 공개 chart `mempool-size`: 공급자가 운영하는 여러 BTC 노드의 대기 집계. 전세계 단일 합의 대기열이나 정확한 확인시간이 아니다. `unit=Bytes, period=minute`이지만 실제 역사 표본은 **900초 간격**이고 소수 byte도 존재한다. 이를 원시 분봉/개별거래 snapshot으로 부르지 않는다. 고정14일 이하 요청 `start=UTCdate,timespan=Ndays,sampled=false,format=json`, 1.05초 이상 간격, 원응답·URL·시각·SHA 보존. 달력2020-01-01~2026-08-29만 정규화한다. [lo,hi)로 자르고 끝 hi 표본은 다음 청크와 동일성만 확인한다. 원천이 다른 해상도를 반환하면 계산 전에 중단·기록하고, 성과를 보고 자료를 고르지 않는다.
2. 매 UTC일 D의 [D,D+1일)에 정렬된 **96개** 집계 관측의 산술평균을 M_D로 정의. 0은 조용한 대기열일 수 있으므로 허용, 음수/비유한/중복상충은 차단. 하나라도 누락하면 그날은 결측, ffill/보간/부분일평균 없음. 정확한 공급자 bin 방향/과거 노드 버전·교체·정책·집계 변경은 미복원. 각 관측을 timestamp+15분 이전에는 완료됐다고 간주하지 않고 일간 M_D는 **D+2일00UTC**부터 가용 처리한다. 이는 실제 최초 게시 빈티지 증명이 아니다.
3. `transaction-fees`는 BTC 단위의 확인된 총 수수료이며 coinbase 신규발행 보상은 제외한다. 고정180일 이하 청크로 같은 날짜 범위 수집. 원본 부동소수 표기는 그대로 보존, 정규화는 Decimal×10^8과 최근접 정수 satoshi의 차이가 **0.0001 sat 이하**일 때만 정수 total_sats로 변환한다. 음수/비유한·더 큰 비정수 잔차는 차단. 0은 그대로 두고 아래 합계 규칙을 적용한다. fee 일간도 D+2일 가용 가정, 누락/중복 일치 감사.
4. 확인 Tx는 기존 `data/btc-network-20261003/network-daily.json` SHA **7a2b322ec2b2c0d4e297eb0c3afa6204f5beaa3d15dcf0531b4b61e2abdeb44a**의 거래 건수만 재사용. 원천 `data/btc-mining-20261002/n-transactions.json` SHA **50756100c7848fe2a7715d39705d7de55338ffc4a9aa4db18a1e990ef7b93adb**, 2025Nov13–15 누락도 그대로. 새 전체 Tx 수집/원시 블록·개별거래 복원 없음. 양수 정수 Tx만 유효.
5. 단위 1,000,000 source Bytes는 로그 변환의 고정 척도일 뿐 용량/블록 수/실제 대기시간으로 환산하지 않는다. Core `getmempoolinfo.bytes`의 vsize와 해당 공급자의 모든 과거 Bytes가 동일하다고 입증하지 않았다. BIP141은 blockweight≤4,000,000, vsize=ceil(weight/4); 현대 평균 serialized block size에 옛1MB 상한을 적용하지 않는다. USD fee/avg-block-size API 표본은 정의 감사일 뿐 신규 입력에 포함하지 않는다.
6. BTC 시장/마스크/완료봉은 기존 그대로: 해제 JSON SHA9909be60d1d4db6b47f766de26894de9cbb55222530f9c3bbdbc19ef0899faa4; spot 무거래 mask SHA bfefb3a32526cfcdf2a5b8151cbfe87f0a749986bbf4cb7d31d7c0d65cf2dfcd. 완료가격 B_t는 직전시간봉 close_time=t−1·양수거래량 종가.

## 고정 피처·상호작용

월요일 T=00UTC의 마지막 일 D=T−2일. `data_delay7`은 세 집계 전부 D=T−9일로 바꾸고 모든 과거 훈련 피처도 같은 방식으로 재구성한다. BTC 가격 통제·위험은 현재 완료가격 그대로다.

최근 집합 A={D−6,…,D}, 이전 집합 B={D−34,…,D−7}. 35일의 M,fee,Tx 전부 있어야 공통 유효하며 Tx>0, M≥0,fee≥0, 두 fee 합계>0가 필요하다.

- z = ln(mean_A(Tx) / mean_B(Tx)): 확인 활동 증가.
- q = ln(1+mean_A(M)/10^6) − ln(1+mean_B(M)/10^6): 공급자 대기압력의 증가. 정확한 대기시간/새로 들어온 순흐름으로 해석하지 않는다. 정책 변경·취소/축출/확인이 감소 원인일 수 있다.
- f = ln((sum_A(total_sats)/sum_A(Tx)) / (sum_B(total_sats)/sum_B(Tx))): BTC-native 확인 수수료/거래의 증가. USD 가격을 곱하지 않고, sat/vbyte나 실제 개별송금의 최적 비용이라고 부르지 않는다. 거래 크기/배칭/코인 가격의 내생성이 남는다.
- x = max(q,0)×max(f,0): 두 압력이 **동시에 증가하는** 결합항. 양·음 둘 다 감소한 주를 높은 혼잡으로 오인하지 않으며 임계0/척도/창을 성과 뒤 조정하지 않는다.
- r7=ln(B_T/B_(T−7일)), r28=ln(B_T/B_(T−28일)); 목표 y_T=ln(B_(T+7일)/B_T).

## 훈련·모형·규칙

2020-01-06~2026-08-31 월요일. 각T의 U∈[T−105주,T−2주], 최대104달력주, 최소52개 유효 완료 label, U+7일≤T−1일. 모든 모형은 같은 유효 훈련/예측 행. 결측 주를 압축하지 않는 달력1주 HAC(Bartlett.5), n/(n−열수) 보정. 중심화 SVD OLS, **모든 계수 부호 무제약**. 랭크부족/비유한/준비부족이면 override 없이 core. 모형·훈련주·label종료·원피처/창 값·계수/cov·μ/SE 보존.

방향 gate는 |μ|>SE+ln(1+.0023)(현물 양수) 또는 SE+ln(1+.0013)(perp 음수). 원천 온체인 fee는 정보 입력이지 우리 거래소 매매 비용에 추가하거나 대신 적용하는 값이 아니다. 실제 온체인 이체/차익 송금 거래는 모의하지 않는다. 비용2배 조건도 신호 gate는 그대로다.

- **BQ_INFO**: INFO와ADD 유효, INFOgate와 δ=μ_INFO−μ_ADD의 동부호 조건 δ×μ_INFO>0 및 |δ|>1e−12를 모두 만족할 때 sign(μ_INFO), 아니면 가격 core.
- BQ_ADD/QUEUE/FEE/ACTIVITY/PRICE: 각 자기 예측 gate 통과 방향, 그 외 core.
- BQ_INV: 기본과 같은 주·위험의 정확히 반대 override, 미발동은 core. 실제 방향별 수량·펀딩 계산.
- BQ_TREND: 항상 기존 E_SPOT core. 기본 일말·회계 항등 필수.

방향은 다음 월요일 전까지 고정, 위험은 매일00UTC의 완료20일 log수익 표본std×√365에서 w=min(1,risk/vol), 기본risk.20/risk10.10. core는 기존20/60/120 momentum+EMA8/32,16/64,32/128 부호평균 s의 max(0,s)×w. 신규 정보 결측은 core, 위험 가격 준비부족은 계획 보류. 평가기점이 주중이면 직전월요일의 이미 작성한 방향을 적용한다.
