# 초기 프로젝트 계획

작성일: 2026-09-29

## 확정된 요청과 미정 사항

요청: 별도 저장소 생성, BTC 선물 자동매매 프로젝트 검토, 월 15만 원 수익을 초기 희망 목표로 설정.
Hyperliquid는 사용자가 제안한 거래소 후보다.

아직 미정: 투자 원금, 총 손실 허용액, 월별 손실 한도, 전략, 매매 주기, 포지션 규모, 실거래 시작 시점.
이 문서의 개발 방향은 제안이며 수익성 검증 결과가 아니다.

## 월 150,000원을 위한 단순 계산

월 필요 수익률 = 150,000원 / 운용 원금. 추가 입출금과 복리는 가정하지 않는다.

| 운용 원금 예시 | 월 필요 수익률 |
| --- | ---: |
| 1,000,000원 | 15% |
| 3,000,000원 | 5% |
| 5,000,000원 | 3% |
| 10,000,000원 | 1.5% |

필요 수익률의 산술 예시일 뿐, 추천 투자금이나 달성 가능한 기대수익률이 아니다.
큰 원금도 손실 위험을 없애지 않으며, 적은 원금을 높은 레버리지로 보완하는 방식은 기본 방향으로 삼지 않는다.

성과 목표의 초기 정의는 **매매 수수료·슬리피지·순펀딩 비용·운영비 차감 후, 구독료 차감 전** 15만 원이다.
세후 실수령 목표인지 여부는 미정이며 세금은 별도로 확인한다.
원화 환산 시점·환율 출처와 USDC 가격 변동도 기록한다.
실현손익과 미실현손익을 함께 표시하고, 평가손실을 숨긴 채 실현수익만 목표 달성으로 보고하지 않는다.

## 첫 검증 범위 제안

- BTC 무기한 선물 한 시장, 규칙 기반 저빈도 전략을 출발점으로 한다.
- 단순 추세추종 등을 연구 후보로 둘 수 있으나, 아직 선정된 전략이나 입증된 우위는 없다.
- 매매하지 않고 현금으로 유지하는 경우와 BTC 단순 보유도 비교 기준으로 둔다.
- 미래 데이터를 사용하지 않고, 전략 개발 구간과 미사용 평가 구간을 시간순으로 분리한다.
- 수수료·스프레드·슬리피지·시간별 펀딩을 반영한다. 지정가 주문이 항상 체결된다고 가정하지 않는다.
- 순손익뿐 아니라 최대 낙폭, 최악의 달, 거래 수, 노출, 연속 손실과 비용 변화에 대한 민감도를 본다.
- 여러 시장 상황과 충분한 표본을 확인한다. 짧은 백테스트나 한 달의 모의 수익만으로 실거래 수익성을 확정하지 않는다.

## 단계별 산출물

1. **조건 정의:** 원금·손실 한도·수익 집계 기준, 첫 전략 가설.
2. **데이터/백테스트:** 재현 가능한 데이터와 비용 모델, 구간 분리 평가 보고서.
3. **모의 운영:** 실시간 시장 데이터로 모의 체결, 잔고·포지션 대사, 중복 주문 방지, 연결 복구 점검.
4. **실거래 검토:** 앞선 결과와 정해진 예산을 바탕으로 별도 결정. 현재 단계에는 포함하지 않는다.

손실·노출 한도와 비상정지는 실거래 코드보다 먼저 설계한다.
손절 주문과 비상정지가 있어도 급변·유동성 부족·장애에서 설정 금액보다 큰 손실이 날 수 있다.

## 운영 구분

기존 게임 프로젝트와 저장소·프로세스를 분리한다.
이번 초기화에서는 기존 서비스, 배포, 자동화 일정, 모델 설정을 변경하지 않는다.
새 유료 API나 외부 데이터 구독은 도입하지 않았다.
