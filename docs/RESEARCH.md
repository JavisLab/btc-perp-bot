# BTC 수익성 검증 환경 v0.2

2026-09-30 / DM1428. 사용자 요청으로 실거래보다 가상 검증을 우선했다.
`btc-research`는 공개 시세와 가상 계좌만 사용한다. 개인키·실계좌·입금은 필요 없다.
기존 `btc-bot` 지갑/주문 코드와 실행 경로를 분리했으며, 자동 실거래 전환 기능은 없다.

## 무엇을 비교하는가

- BTC 기본 무기한 선물 1시간봉: 추세, 돌파, 평균회귀의 고정 3전략.
- 시작 가상 평가자산 1,000 USDC씩, 진입 시 목표 명목 노출 50%. 수수료와 즉시 스프레드 손실을 감안해 수량을 거래 정밀도에 맞춰 절사한다.
- 현금 유지와 같은 노출 비중의 BTC **선물** 매수 후 보유를 함께 비교한다. 현물 매수 수익률이 아니다.
- 앞 70% 개발 / 뒤 30% 평가. 개발 순손익만으로 후보를 정하고 평가 결과는 선택에 사용하지 않는다. 각 구간을 새 가상 계좌로 시작하고 종료 시 비용을 내고 정리한다.
- 기본 비용: 편도 수수료 4.5bp, 반스프레드 0.5bp, 추가 슬리피지 1bp. 양방향 체결마다 반영한다.
- 실제 시간별 펀딩률을 사용하되, 당시 oracle 가격 대신 직전 시간봉 거래 종가로 펀딩 명목금액을 **추정**한다.
- 관측 평가자산 고점 대비 20% 하락 시 전략 신규진입을 멈추고 다음 체결 기회에 정리한다. 최대손실 20% 보장은 아니다. 비교용 현금/선물 보유에는 전략의 20% 중단을 적용하지 않는다.
- 수수료·스프레드·슬리피지 2배와 신호 판단 정보 1시간 추가 지연도 따로 실행한다. 펀딩률은 2배로 바꾸지 않는다. 항상 보유하는 비교기준은 신호 지연의 영향을 받지 않는다.

전략 규칙은 [사전 연구 조건](RESEARCH_PLAN.md)에 고정했다. 결과 확인 후 전략/파라미터를 최적화하지 않았다.
이번 평가 기간을 보고 전략을 바꾸면 이 기간은 더 이상 새 전략의 미사용 검증 구간이 아니다.

## 실행

Python 3.12+, 프로젝트 가상환경. 설치는 루트 README 참조.

```bash
# 1. 실제 공개 원자료 수집. 같은 출력 파일은 덮어쓰지 않는다.
.venv/bin/btc-research collect --days 120 --out data/btc-1h.json

# 2. 네트워크 없이 저장된 원자료로 재현 가능한 비교
.venv/bin/btc-research backtest --data data/btc-1h.json --out runs/experiment-001

# 3. 현재 공개 호가로 6회 관측. 실제 거래소 주문은 전혀 보내지 않는다.
.venv/bin/btc-research paper --state runs/paper.sqlite --steps 6 --interval 10

# 4. 같은 파일로 다시 실행하면 잔고·포지션·비용을 이어간다.
.venv/bin/btc-research paper --state runs/paper.sqlite --steps 6 --interval 10

# 5. 저장한 모든 공개 관측을 오프라인 재생해 계좌·체결·평가값 일치 확인
.venv/bin/btc-research verify-paper --state runs/paper.sqlite

# 6. 보고서 스냅샷 생성. 새 폴더명을 사용한다.
.venv/bin/btc-research paper-report --state runs/paper.sqlite --out runs/paper-snapshot-001
```

출력 `report.html`을 브라우저로 열면 전략별 곡선을 체크박스로 켜고 끌 수 있다.
외부 CDN이나 서버가 필요 없는 독립 파일이다. 폰에서는 넓은 표만 가로로 스크롤한다.
`results.json`, `metrics.csv`, `events.csv`, `equity.csv`도 함께 만든다.
HTML은 생성 시점의 스냅샷이며 자동 갱신 대시보드는 아니다.

장기 모의 관측은 사용자가 `paper --steps 0 --interval 30`으로 시작하고 Ctrl-C로 중단할 수 있다.
종료 시 가상 포지션을 지우거나 초기화하지 않는다. 이번 작업에서는 6회+재시작3회만 실행했으며 상시 서비스는 만들지 않았다.
일시 중단 중의 주문을 과거 가격으로 만들어 넣지 않는다. 보유 중 미처리 펀딩은 기록을 가져와 정산하고, 공백을 보고서에 남긴다.
2분 초과 관측 간격을 공백으로 표시한다. 공백 중 낙폭·손실중단 실행은 알 수 없다.

설정 변경은 `backtest`/`paper`의 `--config config.json`으로 한다. 예:

```json
{"cash":"1000","exposure":"0.5","fee_bps":"4.5","half_spread_bps":"0.5","slippage_bps":"1","max_drawdown":"0.20","train_fraction":"0.70","max_book_slippage_bps":"10"}
```

기존 paper 계좌와 설정 또는 연구 코드 지문이 달라지면 실행을 거부한다. 다른 조건은 새 DB 파일로 분리한다.
계좌 DB에는 금전적 가치가 없는 가상 상태와 공개 데이터만 있고, 지갑 정보는 없다.
원자료/실행 파일은 기본적으로 `data/`, `runs/`에 두며 Git에서 제외한다. 필요한 재현 자료는 별도 백업한다.
이번 첫 비교의 공개 원자료만 예외적으로 [압축 JSON](evidence/research-1428-btc-1h.json.gz)으로 저장소에 보존했다.
새 데이터를 수집하지 않고 정확히 같은 기간을 재현하려면 다음처럼 압축을 푼 뒤 실행한다.

```bash
mkdir -p data
gzip -dc docs/evidence/research-1428-btc-1h.json.gz > data/research-1428-reproduce.json
.venv/bin/btc-research backtest --data data/research-1428-reproduce.json --out runs/reproduce-1428
```

이번 실행은 소켓 네트워크를 차단하고 전체 결과 JSON의 정확한 재현 일치까지 확인했다.

## 검증한 것

- 기존 36개와 신규 28개, **총 64개 자동 검사 통과**. 매수/매도 수수료·펀딩 회계 항등식, 미래 데이터 참조 방지, 평가 구간과 후보 선택의 분리, 비용 민감도, 부분체결/미체결, 포지션 반전 차단, 데이터 무결성 포함.
- 모의계좌의 프로세스 잠금, 트랜잭션 중 실패 시 원자적 롤백, 중복 펀딩 방지, 설정 변경 차단과 재시작 보존 검사.
- 네트워크를 차단한 별도 Python 프로세스에서도 백테스트·보고서 생성 성공. 지갑/거래소 주문 모듈 미로딩 확인.
- 실제 메인넷 공개 호가로 6회 관측 후 프로세스를 다시 실행해 3회 추가, 누적 9회/오류 0. 추세와 보유 계좌가 각각 1회 가상 진입했고 재시작 때 중복 진입 없이 포지션을 유지했다.
- 저장한 9개 관측을 오프라인 재생해 **5개 계좌·9개 평가값 묶음·2개 가상 체결 이벤트 모두 일치**. 이는 짧은 동작 검증이지 장기 수익성/실제 체결 증거가 아니다. 실제 시계의 펀딩 경계를 지난 장기 관측은 아직 수행하지 않았다.
- 독립 HTML 보고서 PC 1280×900/폰 크기390×844의 범례 켜기·끄기, 접기·펼치기, 표 스크롤 검사. 폰 크기에서는 하단까지 실제 스크롤·터치 입력 확인. 브라우저 오류 및 외부 네트워크 요청 0. 실제 휴대전화 검사는 아니다.
- `pip check` 통과. 개인키 열기, 계좌 잔고 조회, 메인넷/테스트넷 주문·입출금·새 daemon은 없음.

## 데이터·체결 모형의 한계

- 공식 캔들 API는 최근 5,000개만 제공하므로 기본120일/최대200일의 1시간봉을 수집한다. 몇 년치 여러 국면을 대표하지 않는다.
- 미래 정보를 쓰지 않도록 닫힌 봉으로 신호를 만들고 다음 봉 시가에 가상 체결한다. 실제 과거 호가 깊이·체결 대기열·봉 내부 경로는 없다.
- 시간봉 백테스트는 펀딩을 시간 경계의 기존 포지션에 정산한 뒤 다음 봉 주문을 처리한다. API의 실제 밀리초 이벤트 순서를 복원한 엔진은 아니다.
- 실제 펀딩률 × 보유 수량 × 직전 시간봉 거래 종가를 사용한다. **공식 정산은 oracle 가격 기준**이므로 그 차이만큼 모형 오차가 생긴다.
- paper는 실제 현재 호가의 양쪽 깊이를 걷고 가상 IOC 가격제한에 따라 일부만 체결되거나 미체결된다. 각 전략은 독립한 가상 책을 사용하며 다른 전략과 유동성을 경쟁하지 않는다. 신호는 새 시간봉당 한 번, 같은 봉의 일반 IOC 미체결은 재시도하지 않지만 위험중단 청산은 다음 관측에서 다시 시도한다.
- 최대낙폭은 관측 시점 기준이고, 정확한 유지증거금·강제청산 엔진은 없다. 진입 후 가격 변동으로 노출/자산 비율이 1배를 넘을 수 있다. 결과를 레버리지 실거래 위험 모형으로 해석하지 않는다.
- 현재 거래 정밀도/고정 기본 수수료를 과거에도 적용한다. 할인·과거 제도 변화·세금·서버비·환율은 제외한다.
- 같은 holdout을 보고 여러 번 전략을 선택하면 과최적화될 수 있다. 이번 결과를 기준으로 새 규칙을 정하더라도 다음 판정에는 새 기간이 필요하다.
