# 테스트넷 주문 검증 — 2026-09-29 / DM1406

## 현재 결과

**검증 프로그램 준비 완료, 실제 거래소 주문·체결 검증은 테스트 자금 부재로 대기 중이다.**

- 기존 v0.1의 26개 검사에 10개 통합/경계 검사를 추가해 **36개 검사 통과**.
- 공식 SDK가 실제 요청 직렬화·서명을 생성하고, 오프라인 교환기 모형에서 서명자와 테스트넷 자산 ID를 검증했다.
- 이 모형은 실제 거래소가 아니다. 실제 Hyperliquid 인증·체결 성공의 증거로 보지 않는다.
- 새 테스트 지갑: 조회한 mainnet/testnet 담보 0, 포지션 0, 미체결 주문 0. 메인넷 비펀딩 원장 조회 결과와 입금 항목도 0.
- 새 명령을 실제 테스트넷에 조회 모드로 실행: BTC 호가/자산 ID 정상 조회, `insufficient_testnet_collateral`로 중단. 서명 요청 0.
- 공식 Faucet는 같은 주소의 메인넷 입금 이력을 요구한다. 새 무입금 지갑에 토큰이 바로 발급된다고 가정하거나 이 조건을 우회하지 않는다. [공식 조건](https://hyperliquid.gitbook.io/hyperliquid-docs/onboarding/testnet-faucet)

실자금 입금·매매·송금, Faucet 청구, 새 서비스/예약 작업은 실행하지 않았다.
기존 테스트 지갑을 사용했으며 추가 지갑을 만들지 않았다. 시드/개인키를 채팅으로 받지 않는다.

## 준비 상태 확인 — 키 불필요

```bash
.venv/bin/btc-bot testnet-smoke --account 0x테스트할계좌의공개주소
```

공식 testnet endpoint만 사용한다. `--network mainnet` 옵션이 없으며, 내부에서도 다른 네트워크/URL을 거부한다.
기본은 시세/계좌 조회와 로컬 결과 기록만 한다. `--keystore`를 함께 지정해도 실행 옵션이 없으면 복호화하거나 서명하지 않는다.

시작 조건:

- 테스트 담보가 설정한 주문 한도 이상일 것.
- 모든 포지션이 0이고 미체결 주문이 없을 것.
- 해결되지 않은 요청 journal이 없을 것.
- BTC 시세가 신선하고, 수량을 거래 단위로 내린 뒤에도 주문 금액이 거래소 최소값 이상일 것.

이 검사에서 `ready_check_only`가 나와도 **API wallet 권한/서명 승인이 입증되는 것은 아니다**.
준비 검사 결과는 `blocked` 또는 `ready_check_only`이고, 실제 주문 검사를 마쳐야 `completed`가 된다.

## 테스트 잔고 확보 후 한 번의 검증

```bash
.venv/bin/btc-bot testnet-smoke \
  --account 0x테스트할계좌의공개주소 \
  --keystore ~/.local/share/btc-perp-bot/wallets/testnet.keystore.json \
  --execute-testnet-orders
```

원래 사용자 키면 `--account`는 그 주소다. 승인된 테스트넷 API wallet 키라면 `--account`에는 원래 사용자 계좌 주소를 쓴다.
암호는 비표시 터미널 입력 또는 0600 권한 `--password-file`로 전달한다. 개인키·암호를 명령행 문자열에 넣지 않는다.
신규로 만든 계좌가 담보 부족이면 **개인키를 열기 전** 중단한다.

정상 경로는 서명 요청 4번으로 한정된다:

1. 현재 bid보다 약 1% 낮은 BTC post-only 매수 주문 → 조회로 `open` 확인.
2. 해당 주문 취소 → 조회로 `canceled`, 미체결 0, BTC 포지션 0 확인.
3. IOC 매수 → 응답의 실제 체결 수량과 계좌 포지션 대조.
4. 그 실제 수량만 reduce-only IOC 매도 → 포지션 0, 미체결 0 및 양쪽 주문의 거래소 체결 내역 대조.

기본 명목 한도 25 **mock USDC**, 명령의 허용 범위 12~100이다. 기능 검증용 제한이지 투자 금액 추천이 아니다.
입력 금액을 모두 쓰는 것이 아니라 수량 단위와 여유를 반영해 내림한다.
공식 perpetual 신규 주문의 최소 명목값은 $10이며, 수량 내림 후 이 값에 못 미치면 차단한다. [공식 오류 규격](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/error-responses)

체결/취소 반영 지연에는 **조회만** 제한적으로 반복한다. 서명 주문을 자동으로 다시 보내지 않는다.
부분 진입은 실제 체결분만 청산한다. 부분 청산이면 성공 처리하지 않고 중단한다.
체결 응답만으로 완료 처리하지 않으며 `userFillsByTime`의 주문 ID·방향·총수량이 일치해야 한다.

## 실패 시

- `runs/날짜-smoke-ID/summary.json`과 단계별 JSON에 관측 결과를 저장한다. 이 경로는 Git에서 제외한다.
- 응답이 사라졌거나 주문 상태/체결 내역을 확인하지 못하면 실패로 기록한다. 포지션/주문이 남을 수 있다.
- 오류·강제 종료 때 자동 청산/취소 요청을 추가 전송하지 않는다. 원인이 불명확한 채 전체 검사를 다시 실행하지 않는다.
- `order-status`, `account`, `reconcile`로 상태를 먼저 확인한다. 미해결 journal 삭제로 우회하지 않는다.
- 일정 금액 이익, 실제 손실 제한, 장기 운용, 수익금 송금은 이 검증의 범위가 아니다.
